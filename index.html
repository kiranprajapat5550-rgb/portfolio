How I approach problems

Case study snapshots

Portfolio prototypes, with the problem, approach and honest implementation status made explicit.

Case 01 · Reporting

Make sales data easier to review

Problem: Raw order rows can make performance hard to scan quickly.

Approach: Calculate revenue, order count, average order value and category/month summaries from a consistent CSV schema.

Validation: Test with the included fictional sample CSV and compare totals against the source rows.

Status: Local browser prototype; no live data connection or measured business impact claimed.

Try the sales tool →
Case 02 · Inventory

Surface stock exceptions sooner

Problem: Low stock, expiry dates and stale movement records can be easy to overlook in a spreadsheet.

Approach: Flag rows for human review using quantity, reorder level, expiry date and last-movement date.

Validation: Use fictional sample rows and inspect the exported flagged list before acting.

Status: Rule-based prototype; not connected to a stock system and not a substitute for policy checks.

Try the inventory tool →
Case 03 · Appointments

Structure a booking handoff

Problem: Appointment requests need clear time slots and status visibility.

Approach: Prototype reference-based entries, overlap checks and status tracking.

Validation: Test conflicting slots and review the exported CSV using fictional references only.

Status: In-memory demo; no live calendar, messaging or patient-data integration.

Try the appointment tracker →
Case 04 · AI governance

Keep proposed AI actions reviewable

Problem: Automated workflows need a clear human checkpoint before consequential actions.

Approach: Simulate an approval queue with approve/reject decisions and a local audit trail.

Validation: Test both decisions and inspect the exported trail.

Status: Simulation only; no external actions, credentials, or live AI agent are enabled.

Try the approval desk →
